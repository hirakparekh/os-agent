Retrieval-augmented generation — architecture patterns

Three ways to ground an LLM in your own data

Vector RAG, GraphRAG, and a hierarchical alternative — guardrailed tree RAG — side by side, drawn as the mechanism each one actually runs, not just the name.

01 Vector RAG

Every document is chunked and embedded once at index time. At query time the question is embedded too, matched against the flat index by similarity, and the top-k chunks are handed to the LLM to answer from.

02 GraphRAG

Documents are mined for entities and relationships, clustered into communities, and each community is summarized by the LLM. Answering forks in two: a local search walks the entity subgraph for specific questions; a global search maps over every community summary for broad, thematic ones.

03 Guardrailed Tree RAG — this system

Each item is classified into a fixed category/topic hierarchy by the LLM, then checked by a deterministic keyword scorer that can overrule a wrong guess before anything is written. A question is answered by walking straight to the matching branch — no similarity search, no clustering, one generation call.
